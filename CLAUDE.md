# Рабочие соглашения / Working Conventions

Этот файл — единая точка истины о том, как устроена и пишется эта библиотека. Читается **людьми и AI-помощниками** (Claude, Copilot, Cursor и т.п.). При работе над библиотекой AI-помощникам следует сначала прочитать этот файл, прежде чем что-либо менять.

---

## О репозитории

Открытая библиотека шаблонов IT-политик для русскоязычных организаций. Цель — дать сообществу качественные, связанные между собой и применимые шаблоны политик, регламентов и стандартов.

**Принципы:**
1. **Полнота важнее красоты.** Лучше есть шаблон, чем его нет.
2. **Связность важнее изоляции.** Каждый шаблон знает, от чего он зависит и с чем связан.
3. **Применимость важнее академичности.** Маркеры зрелости и условности должны помогать выбирать, а не пугать объёмом.
4. **Реальность важнее догмы.** Политика, противоречащая практике, опаснее её отсутствия.

## Языковые соглашения

### Что на каком языке

| Элемент | Язык |
|---|---|
| Содержимое всех `*.md` файлов | Русский |
| Заголовки внутри документов | Русский |
| Имена директорий и файлов | Английский, lowercase-hyphenated |
| ID шаблонов (`POL-IAM-001`) | Английский |
| Ключи в `metadata.yml` | Английский |
| Значения в `metadata.yml` (где это текст) | Русский, кроме enum-значений |
| Названия фреймворков в regulatory_refs | Оригинал (ISO/IEC, ФСТЭК и т.д.) |

### Тон

- Формальный, но человеческий — без бюрократического канцелярита
- Прямой и конкретный — без «следует отметить» и «представляется целесообразным»
- Без снисхождения к читателю, но и без агрессивного жаргона
- Объяснять «зачем», а не только «что»

### Стандартизованная терминология

| Термин | Используем | Не используем |
|---|---|---|
| Контроль доступа | управление доступом | контроль за доступом |
| Подрядчик | подрядчик | контрактор |
| Сотрудник | сотрудник | работник, юзер |
| Пользователь системы | пользователь | юзер |
| Учётная запись | учётная запись | аккаунт (кроме облачных контекстов) |
| Резервное копирование | резервное копирование | бэкап (в content); в названиях можно |

## Структура папки шаблона

Каждый шаблон политики живёт в отдельной папке `policies/<domain>/<slug>/`:

```
policies/02-access-control/password-policy/
├── README.md         ← описание шаблона, зачем он нужен, контекст
├── TEMPLATE.md       ← сам шаблон с плейсхолдерами
├── GUIDE.md          ← как применять, частые ошибки, советы
├── metadata.yml      ← машиночитаемые метаданные
├── CHANGELOG.md      ← история этого шаблона
└── EXAMPLES/         ← опционально, анонимизированные примеры
```

**Все шесть позиций обязательны** (EXAMPLES — опционально). Без любого из них шаблон считается недоделанным.

## Схема `metadata.yml`

См. файл `policies/_TEMPLATE/metadata.yml` для канонического примера со всеми полями.

**Обязательные поля:**

```yaml
id: POL-IAM-001                  # формат POL-<DOMAIN>-<NUMBER>
title: Политика управления паролями
slug: password-policy            # имя папки
domain: 02-access-control        # имя домена-папки
version: 1.0                     # semver
status: draft                    # draft | review | active | deprecated
maturity: core                   # core | standard | advanced
conditional: false               # true → шаблон условный (ⓘ)
typical_owner: CISO              # типичная роль-владелец
last_reviewed: 2026-05-11
review_cycle_months: 12
```

**Необязательные, но желательные:**

```yaml
short_title: Пароли              # для индексов и графов
depends_on:                      # ID шаблонов, которые должны быть раньше
  - POL-GOV-001
related_to:                      # ID соседних шаблонов
  - POL-IAM-002
regulatory_refs:                 # маппинг на стандарты
  - "ISO/IEC 27001:2022 — A.5.17"
  - "ФЗ-152 — ст. 19"
  - "ФСТЭК Приказ 17 — ИАФ.3"
packs:                           # в какие готовые наборы входит
  - minimum-starter
tags:
  - access-control
  - identity
applicability_notes: |           # если conditional: true
  Применима для организаций ...
authors:
  - iMironRU
```

**Невалидный metadata.yml — невалидный PR.** Скрипт `tools/validate-metadata.py` проверяет схему.

## Маркеры применимости

В содержании документов и индексах используются маркеры:

- **★ Core** — базовый уровень, нужно почти всем
- **◆ Standard** — средний уровень, средний и крупный бизнес
- **▲ Advanced** — продвинутый, зрелые или регулируемые организации
- **ⓘ Conditional** — только если применимо (отрасль, размер, регуляторика)

В `metadata.yml` это два поля: `maturity` (core/standard/advanced) и `conditional` (boolean).

## Соглашения по содержанию шаблонов

### Структура TEMPLATE.md

Каждый TEMPLATE.md следует единой структуре:

```markdown
# {Название политики}

**Версия:** {{ВЕРСИЯ}}
**Дата утверждения:** {{ДАТА}}
**Владелец:** {{РОЛЬ-ВЛАДЕЛЕЦ}}
**Утверждающий:** {{РОЛЬ-УТВЕРЖДАЮЩИЙ}}

## 1. Назначение

[Зачем существует эта политика, какую проблему решает]

## 2. Область применения

[На кого распространяется: сотрудники, подрядчики, системы]

## 3. Термины и сокращения

[Используемые в документе термины]

## 4. Положения

[Сами требования политики]

## 5. Ответственность

[Кто за что отвечает]

## 6. Контроль соблюдения

[Как проверяется выполнение]

## 7. Ответственность за нарушения

[Последствия]

## 8. Связанные документы

[Ссылки на другие политики и регламенты]

## 9. История изменений

[Версии]
```

Конкретные разделы можно адаптировать под содержание, но **разделы 1, 2, 4, 5, 8 обязательны** для всех шаблонов.

### Плейсхолдеры

В шаблонах используются плейсхолдеры двух видов:

- `{{ПЛЕЙСХОЛДЕР}}` — переменное значение, которое организация подставляет (например, `{{НАЗВАНИЕ_ОРГАНИЗАЦИИ}}`, `{{СРОК_ХРАНЕНИЯ}}`)
- `[ВПИСАТЬ: краткое пояснение]` — место, где организация должна вписать свою специфику (например, `[ВПИСАТЬ: список разрешённых браузеров]`)

Список плейсхолдеров шаблона — в начале TEMPLATE.md или в GUIDE.md.

### Cross-references

Ссылки между шаблонами — по ID:

```markdown
См. также [Политика паролей (POL-IAM-001)](../password-policy/TEMPLATE.md).
```

В тексте политики, который пойдёт в организацию, плейсхолдеры для собственных документов:

```markdown
См. также {{ССЫЛКА_НА_ПОЛИТИКУ_ПАРОЛЕЙ}}.
```

## Жизненный цикл шаблона

```
draft → review → active → (deprecated)
```

- **draft** — в работе, ещё не готов к использованию
- **review** — готов, в ревью; не рекомендуем для прода
- **active** — готовый, рекомендованный к использованию
- **deprecated** — устаревший, не рекомендуется; в metadata должен быть `superseded_by: POL-XXX-NNN`

Переход draft → review требует заполненности всех обязательных полей и всех шести файлов.
Переход review → active требует минимум одного PR-ревью.

## Когда добавлять новый шаблон

Добавляйте новый шаблон, если:

1. Он покрывает реальную проблему/обязанность, не покрытую существующими
2. Он самостоятельный (не подраздел существующего)
3. У него есть свой жизненный цикл и владелец
4. Его метаданные можно заполнить полностью

**Не добавляйте** новый шаблон, если:

- Он на 80% дублирует существующий — лучше PR в существующий
- Он слишком узкий и был бы разделом другого
- У него нет ясного контекста применимости

## Использование AI для написания шаблонов

AI (Claude, Copilot, GPT) — полезный инструмент для драфтинга, но:

1. **Никогда не публикуйте AI-сгенерированный шаблон без человеческого ревью.** Это противоречит принципу качества.
2. **Подсказывайте AI этот файл.** Дайте CLAUDE.md в контекст — это даёт правильный стиль и структуру.
3. **Проверяйте регуляторные ссылки.** AI часто галлюцинирует номера статей и пунктов.
4. **Помечайте AI-вклад.** В CHANGELOG шаблона: «Изначальный драфт сгенерирован Claude Sonnet 4.6, отредактирован вручную».
5. **Не загружайте чувствительные данные.** Шаблоны публичные, но если адаптируете под конкретную организацию — это уже её данные, и в публичный AI их грузить нельзя.

## Иерархия документов

Когда непонятно, как называть документ — «политика», «стандарт», «регламент», «инструкция»:

```
Политика     — что и зачем (1-3 страницы, принципы)
↓
Стандарт     — требования (что должно соблюдаться, конкретные параметры)
↓
Регламент    — процедура (последовательность шагов в процессе)
↓
Инструкция   — как именно (пошаговое, для конкретной роли)
```

В этой библиотеке всё лежит под общим зонтиком «политика», но **в названии конкретного шаблона** уточняйте тип, если он не «политика»:

- `password-policy` — политика
- `naming-standard` — стандарт
- `incident-response-procedure` — регламент
- `vpn-setup-instruction` — инструкция

## Что нельзя делать

1. **Менять ID существующего шаблона.** Это сломает все ссылки. Если переименование критично — создаётся новый шаблон с `supersedes: <old-id>`, старый помечается как deprecated.
2. **Удалять шаблон с историей.** Только deprecation.
3. **Пушить в `main` напрямую.** Только через PR с ревью.
4. **Публиковать конфиденциальную информацию реальных организаций.** EXAMPLES должны быть анонимизированы.
5. **Использовать персональные данные в плейсхолдерах.** Никаких реальных ФИО, телефонов, ИНН.
