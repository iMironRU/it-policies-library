# История изменений — POL-OPS-001 Политика управления изменениями в IT-инфраструктуре

## [1.0.0] — 2026-10-02

### Added
- Первоначальная версия шаблона
- Три типа изменений: стандартное (с реестром), нормальное (Minor/Major), экстренное
- RFC с обязательными полями: описание, обоснование, оценка рисков, план реализации, rollback-план, критерии успеха
- Процедура нормального изменения: подача RFC → оценка риска → согласование → реализация → PIR
- CAB ({{РОЛЬ_CAB}}): состав, периодичность {{ПЕРИОДИЧНОСТЬ_CAB}}, полномочия (утверждение/доработка/отклонение)
- Критерии и порядок отката (rollback): условия активации, принятие решения без связи с менеджером
- Анализ после внедрения (PIR): для всех Major и экстренных изменений, срок — 5 рабочих дней
- Реестр изменений в {{СИСТЕМА_УЧЁТА_ИЗМЕНЕНИЙ}}: поля, срок хранения {{СРОК_ХРАНЕНИЯ_RFC}}
- CMDB: обновление в течение 1 рабочего дня, актуализация как часть закрытия RFC
- Freeze-периоды: запрет изменений, исключения (только экстренные + угрозы ИБ), уведомление за 5 рабочих дней
- Безопасность изменений: обязательная ИБ-оценка для ПДн/ГИС/КИИ; минимальный доступ на период изменений; обязательное согласование {{РОЛЬ_ИБ}} для изменений конфигураций безопасности
- Неавторизованные изменения: уведомление → оценка → откат → расследование как инцидент ИБ
- Матрица ответственности: Менеджер изменений, CAB, Владелец системы, ИБ, Инициатор, руководство
- Метрики: доля успешных изменений (≥ 95%), PIR-покрытие (100% для Major/Экстренных), CII, доля неавторизованных (0%)
- Маппинг на ISO/IEC 27001:2022 A.8.32; ISO 20000-1 8.5; CIS Controls v8 4.1; NIST SP 800-53 CM-3/CM-4; ФЗ-152 ст. 19 ч. 2; ФСТЭК Приказ 21 УКФ.1–УКФ.6; Приказ 17 УКФ.1–УКФ.4
- Руководство по применению (GUIDE.md): масштабирование по размеру организации, критерии Minor/Major, реестр стандартных изменений, rollback на практике, обработка экстренных изменений, freeze-периоды, требования ИСПДн/ГИС
