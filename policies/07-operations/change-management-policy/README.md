**Владелец:** IT-директор  

---

## Зачем нужна эта политика

Неконтролируемые изменения — одна из ведущих причин инцидентов в IT. По данным ITIL-практики, значительная доля инцидентов доступности напрямую связана с изменениями, реализованными без надлежащей оценки рисков или документации.

Эта политика устанавливает базовые требования к процессу управления изменениями, применимые для любой организации: от малого бизнеса с несколькими серверами до крупных компаний с развитой ITSM-практикой. Она отвечает на вопросы: как классифицировать изменения, кто что согласует, как обращаться с экстренными ситуациями и когда изменения вообще запрещены.

## Что покрывает шаблон

| Область | Содержание |
|---|---|
| Классификация | Стандартные / Нормальные (Minor/Major) / Экстренные изменения |
| Процедура | RFC → оценка → согласование (CAB или Менеджер) → реализация → PIR |
| Rollback | Критерии и порядок отката, принятие решений в нештатной ситуации |
| Freeze-периоды | Запрет изменений в критичные периоды, исключения |
| Безопасность | Обязательная оценка ИБ для изменений в ПДн/ГИС/КИИ-системах |
| Неавторизованные изменения | Обнаружение, расследование, откат |
| Метрики | CII, доля успешных изменений, PIR-покрытие |
| CMDB | Обновление конфигурационной базы при каждом изменении |

## Как использовать этот шаблон

1. Заполните плейсхолдеры — особое внимание на `{{РОЛЬ_CAB}}`, `{{ПЕРИОДИЧНОСТЬ_CAB}}` и `{{FREEZE_ПЕРИОДЫ}}`.
2. Определите состав CAB: для малых организаций это может быть IT-директор + CISO + представитель бизнеса; для крупных — формальный комитет.
3. Заполните реестр стандартных изменений (типовые операции, не требующие полной процедуры).
4. Согласуйте freeze-периоды с бизнесом заранее.
5. Подробные советы — в `GUIDE.md`.

## Ограничения шаблона

- Шаблон описывает политику (что и зачем), но не детальную процедуру (пошаговые инструкции). Для каждой роли рекомендуется разработать отдельную рабочую инструкцию.
- Шаблон не описывает технические инструменты (ITSM-системы): выбор и настройку Jira, ServiceNow или аналогов организация определяет самостоятельно.
- Для организаций с зрелой ITSM-практикой (ITIL v4 full implementation) этот шаблон — базовый уровень; расширяйте его Release Management, Service Validation и другими практиками.
