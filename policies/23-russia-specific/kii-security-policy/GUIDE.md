# GUIDE — POL-RUS-001 Политика обеспечения безопасности объектов КИИ

Практическое руководство: как провести категорирование, подготовить документы для ФСТЭК и выстроить взаимодействие с НКЦКИ.

---

## Шаг 1. Определить, является ли организация субъектом КИИ

### Критерии субъекта КИИ (ФЗ-187 ст. 2)

Организация является **субъектом КИИ**, если выполняются оба условия:

1. Деятельность ведётся в одной из 12 сфер:
   - здравоохранение
   - наука
   - транспорт
   - связь
   - энергетика
   - банки и иные финансовые организации
   - ТЭК
   - атомная энергетика
   - оборонная промышленность
   - ракетно-космическая промышленность
   - горнодобывающая промышленность
   - металлургическая и химическая промышленность

2. Организации принадлежат (на праве собственности, аренды или ином) ИС, ИТК-сети или АСУ, используемые в указанной сфере деятельности.

> Если оба условия выполнены — организация субъект КИИ, даже если она ещё не проводила категорирование.

### Типовые объекты КИИ (примеры по отраслям)

| Отрасль | Типовые объекты КИИ |
|---|---|
| Энергетика | АСУ ТП электростанций, ИС диспетчерского управления |
| Финансы | АБС (автоматизированные банковские системы), процессинговые центры |
| Транспорт | Системы управления воздушным движением, АСУ железной дороги |
| Здравоохранение | МИС (медицинские информационные системы), системы лучевой диагностики |
| Связь | Системы управления сетями связи, узлы коммутации |

## Шаг 2. Провести категорирование

### Кто проводит

Категорирование проводит постоянно действующая **комиссия субъекта КИИ** (ПП РФ № 127 п. 11). В состав включаются:
- руководитель организации или его заместитель;
- специалисты по ИБ;
- специалисты по эксплуатации ИС/АСУ;
- юристы;
- представители подразделений, зависящих от конкретных ИС.

### Что делает комиссия

1. **Составляет перечень объектов** — все ИС, ИТК-сети, АСУ, которые могут быть объектами КИИ.
2. **Выявляет критические процессы** — производственные, управленческие, финансовые и иные процессы, нарушение которых повлечёт значительный ущерб.
3. **Оценивает показатели критериев значимости** по 5 группам (ПП № 127, приложение):
   - Социальная значимость (число пострадавших, масштаб нарушения жизнедеятельности)
   - Политическая значимость (ущерб органам власти, международные последствия)
   - Экономическая значимость (размер прямого ущерба)
   - Значимость для обороны и безопасности
   - Экологическая значимость
4. **Присваивает категорию** на основании наивысшего показателя из пяти групп:

| Категория | Характеристика |
|---|---|
| 1 (высшая) | Значительный ущерб одному из критериев в крупном масштабе |
| 2 | Ущерб в среднем масштабе |
| 3 | Ущерб в малом масштабе |
| Нет категории | Объект не является значимым |

### Документы по итогам категорирования

Комиссия оформляет **акт категорирования** по каждому объекту. Форма акта — в ПП РФ № 127 (приложение 1). Акт должен содержать:
- сведения об объекте (наименование, назначение, владелец);
- описание критических процессов;
- результаты оценки по каждому критерию;
- итоговую категорию;
- подписи членов комиссии.

### Направление сведений в ФСТЭК

В течение **10 дней** после утверждения актов направить во ФСТЭК:
- перечень объектов КИИ с категориями;
- акты категорирования.

Адресат: территориальный орган ФСТЭК России или центральный аппарат (в зависимости от отраслевой принадлежности). Форма для направления — утверждена Приказом ФСТЭК № 227 от 22.12.2017.

## Шаг 3. Разработать систему безопасности значимого объекта

### Последовательность

```
Исходные данные → Модель угроз → Требования к СЗ → Технический проект → Внедрение → Испытания → Ввод в эксплуатацию
```

**1. Сбор исходных данных**: назначение объекта, состав компонентов, пользователи, сетевые подключения, уже применяемые меры.

**2. Разработка модели угроз и нарушителя**: в соответствии с Методикой ФСТЭК (утверждена 05.02.2021). Модель должна отвечать на вопросы: кто атакует, с какой целью, через какие векторы.

**3. Определение требований к системе безопасности**: на основе категории значимости и модели угроз — выбрать состав мер из Приказа ФСТЭК № 239 (Приложения 1–3).

**4. Технический проект**: проектная документация на систему безопасности, включающая архитектурные решения, перечень СЗИ, схему сети, ролевую модель доступа.

**5. Внедрение и настройка СЗИ**: только сертифицированные ФСТЭК средства защиты.

**6. Испытания**: функциональное тестирование каждой меры защиты; оформление протоколов.

**7. Ввод в эксплуатацию**: приёмо-сдаточные испытания; формирование эксплуатационной документации.

## Взаимодействие с НКЦКИ: практика

### Как подключиться

1. Направить заявку на регистрацию в НКЦКИ через portal.ki.fgov.ru (портал ГосСОПКА).
2. Пройти идентификацию организации.
3. Получить идентификатор организации и реквизиты подключения.
4. Настроить передачу сведений об инцидентах через API ГосСОПКА или личный кабинет.

### Что уведомлять

Уведомлению подлежат **компьютерные инциденты** на объектах КИИ — в соответствии с Приказом ФСБ № 367:
- несанкционированный доступ к объекту;
- заражение вредоносным ПО;
- нарушение доступности объекта;
- изменение конфигурации без санкции;
- иные события, нарушающие безопасность.

### Шаблон первичного уведомления

```
1. Дата и время обнаружения инцидента
2. Наименование объекта КИИ (категория значимости)
3. Тип инцидента (по классификатору НКЦКИ)
4. Краткое описание: что произошло, затронутые компоненты
5. Предпринятые меры по локализации
6. Контактное лицо: ФИО, должность, телефон, e-mail
```

## Проверка ФСТЭК: что ожидать

ФСТЭК проверяет субъектов КИИ в плановом и внеплановом режиме (ФЗ-187 ст. 13). При подготовке к проверке рекомендуется:

```
Документы, которые запросит ФСТЭК:
□ Приказ о создании комиссии по категорированию
□ Перечень объектов КИИ
□ Акты категорирования по всем объектам
□ Акт направления сведений в ФСТЭК (с отметкой о приёмке)
□ Модели угроз и нарушителя
□ Технические задания на системы безопасности
□ Технические проекты на системы безопасности
□ Протоколы испытаний
□ Сертификаты на применяемые СЗИ
□ Регламенты и инструкции по эксплуатации систем безопасности
□ Журналы событий безопасности (за проверяемый период)
□ Планы устранения несоответствий (если есть открытые пункты)
```
