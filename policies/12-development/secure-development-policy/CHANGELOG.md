# История изменений — POL-DEV-001 Политика безопасной разработки программного обеспечения

## [1.0.0] — 2026-10-02

### Added
- Первоначальная версия шаблона
- Принципы безопасной разработки: security by design, shift-left, минимальные привилегии, разделение сред
- Требования к управлению исходным кодом: защита веток, code review, доступы
- Требования по этапам SSDLC: проектирование (threat modeling), разработка (secure coding, запрет секретов), тестирование (SAST/DAST/SCA/пентест), релиз (release gates), эксплуатация
- Управление сторонними зависимостями с автоматическим мониторингом CVE
- Управление секретами: хранение в vault, ротация, процедура при утечке
- Таблица SLA по устранению уязвимостей (Critical → 72 ч в продакшене, High → 14 дней, Medium → 30 дней)
- Требования к обучению разработчиков (OWASP Top 10, при найме + ежегодно)
- Маппинг на ISO/IEC 27001:2022 A.8.25–A.8.34, NIST SP 800-218, OWASP SAMM, ГОСТ Р 56939-2016, ФЗ-152 ст. 19
- Полное руководство по применению (GUIDE.md): выбор инструментов, приоритизация внедрения, типичные ошибки, метрики зрелости
