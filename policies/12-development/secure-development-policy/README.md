# POL-DEV-001 — Политика безопасной разработки программного обеспечения

**Статус:** Draft · **Зрелость:** ◆ Standard · **Версия:** 1.0

## Зачем нужна эта политика

Уязвимости, внесённые на этапе разработки, — самый дешёвый класс проблем в производстве и самый дорогой в эксплуатации. Политика фиксирует минимальный набор требований безопасности, которые разработчики, тестировщики и DevOps-инженеры обязаны выполнять на каждом этапе жизненного цикла: от проектирования до вывода продукта из эксплуатации.

## Контекст применения

Подходит для организаций, которые:

- Разрабатывают собственное программное обеспечение (веб, мобильные, desktop, API, внутренние инструменты)
- Используют внешних подрядчиков для разработки
- Имеют небольшую команду без выделенной роли Application Security

Для крупных продуктовых компаний с зрелым AppSec-процессом политика служит базовым уровнем; поверх неё можно строить более детальные стандарты (стандарт безопасного кодирования, стандарт управления зависимостями и т.д.).

## Зависимости

Политика предполагает, что в организации уже действуют:

- **POL-GOV-001** — Политика информационной безопасности (устанавливает принципы и структуру ИБ)
- **POL-GOV-002** — Политика классификации информации (определяет чувствительность данных, которые обрабатывает ПО)

## Владелец и ревьюер

- **Типичный владелец:** CISO или руководитель разработки
- **Ревьюер при обновлении:** Технический директор, Lead Developer, DevOps-лидер
- **Цикл пересмотра:** Ежегодно или при существенном изменении стека технологий
