# История изменений — POL-MTA-001 Политика управления IT-политиками

## [1.0.0] — 2026-10-03

### Added
- Первоначальная версия шаблона
- Иерархия документов: четыре уровня (политика → стандарт → регламент → инструкция) с правилом приоритета при конфликте
- Жизненный цикл политики: 4 статуса (draft/review/active/deprecated) с явными критериями перехода; инициирование, разработка, согласование, утверждение
- Плановое ревью: периодичность через `{{СРОК_ПЛАНОВОГО_РЕВЬЮ}}`; три исхода (без изменений / обновление / вывод из действия); обязательное обновление `last_reviewed`
- Внеплановое ревью: 5 триггеров (изменение законодательства, инцидент, M&A, решение руководства, инициатива владельца); срок инициирования `{{СРОК_ВНЕПЛАНОВОГО_РЕВЬЮ}}`
- Версионирование major/minor: major — повторное утверждение; minor — одобрение владельца
- Вывод из действия: `superseded_by`, уведомление сотрудников, архивирование `{{СРОК_ХРАНЕНИЯ_УСТАРЕВШИХ}}`
- Реестр политик: состав метаданных, ответственный (CISO), принцип единственного источника истины
- Доведение до сотрудников: публикация в портале, подтверждение ознакомления `{{СРОК_ОЗНАКОМЛЕНИЯ}}`, онбординг, обучение при существенных обновлениях
- Управление исключениями: основания (техническая неприменимость, несоразмерность затрат, компенсирующий контроль); 4-шаговая процедура запроса; ограничения (максимальный срок, запрет законодательных исключений); критические отклонения `{{СРОК_УСТРАНЕНИЯ_КРИТИЧЕСКОГО_ИСКЛЮЧЕНИЯ}}`
- Матрица ответственности: 7 ролей (Утверждающий, CISO, IT-директор, Юридическая служба, Владельцы, Руководители, Сотрудники)
- GUIDE.md: порядок внедрения (4 шага), механизмы подтверждения ознакомления, практика управления исключениями, адаптация для малых организаций, маппинг на ISO/IEC 27001:2022 A.5.1

### Исправления (по результатам AI-ревью)
- §4: убран хардкоженый диапазон «1–2 года» для уровня Policy → заменён ссылкой на `{{СРОК_ПЛАНОВОГО_РЕВЬЮ}}` для согласованности с §5.5
- §5.1: добавлен явный переход `review → draft` при поступлении существенных замечаний, требующих переработки; уточнено «ревью» → «согласование» для отличия от «планового ревью»
- §5.5: добавлена эскалация при пропуске срока планового ревью — CISO направляет предупреждение; при отсутствии реакции 14 дней инициирует ревью самостоятельно
