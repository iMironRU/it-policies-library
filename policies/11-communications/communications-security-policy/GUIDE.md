# GUIDE — POL-COM-001 Политика безопасности корпоративных коммуникаций

Руководство по внедрению: как настроить защиту почты, выбрать корпоративный мессенджер и научить сотрудников распознавать фишинг.

## Настройка SPF / DKIM / DMARC

Три записи DNS, которые не дадут злоумышленникам слать письма от вашего имени.

### SPF

```dns
# Разрешить только ваш почтовый сервер и Office 365:
v=spf1 ip4:1.2.3.4 include:spf.protection.outlook.com ~all

# Только ваш сервер:
v=spf1 ip4:1.2.3.4 -all
```

**Начните с `~all` (softfail)** — чужие серверы помечаются спамом, но не отклоняются. Переходите на `-all` после того, как убедитесь, что учтены все легитимные серверы отправки (CRM, рассыльщик новостей, ERP и т.д.).

### DKIM

```bash
# Генерация ключа (на Postfix/Linux):
opendkim-genkey -t -s mail -d company.ru
# Публикует в DNS: mail._domainkey.company.ru TXT "v=DKIM1; k=rsa; p=<публичный ключ>"
```

Для Exchange/Microsoft 365 — включается в защитных настройках Exchange Admin Center → DKIM.

### DMARC

```dns
# Стартовый вариант (только мониторинг):
_dmarc.company.ru TXT "v=DMARC1; p=none; rua=mailto:dmarc@company.ru; ruf=mailto:dmarc@company.ru; fo=1"

# После анализа отчётов — quarantine:
v=DMARC1; p=quarantine; pct=50; rua=mailto:dmarc@company.ru

# Финальный вариант:
v=DMARC1; p=reject; rua=mailto:dmarc@company.ru
```

**Этапы внедрения DMARC:**
1. `p=none` — сбор отчётов, 2–4 недели.
2. Анализ отчётов (инструменты: dmarcian, Postmark DMARC, MXToolbox).
3. Исправление всех легитимных серверов отправки в SPF.
4. `p=quarantine; pct=10` → `pct=50` → `pct=100`.
5. `p=reject`.

## Выбор корпоративного мессенджера

### Критерии для российских организаций

| Критерий | Что важно |
|---|---|
| Хранение данных в РФ | Для ПДн граждан РФ — обязательно (ч. 5 ст. 18 ФЗ-152) |
| On-premise / SaaS | On-premise — полный контроль, выше стоимость; SaaS — быстрый старт |
| SSO/SCIM | Необходим для централизованного управления аккаунтами |
| E2EE | Для конфиденциальных переговоров |
| Аудит-логи | Необходимы для расследований |
| Включён в реестр Минцифры | Для госсектора и субъектов КИИ |

### Сравнение популярных решений

| Решение | Тип | Данные в РФ | SSO | E2EE | Реестр Минцифры |
|---|---|---|---|---|---|
| TrueConf | On-premise / SaaS | Да | Да | Да | Да |
| VK Teams (Mail.ru for Business) | SaaS | Да | Да | Частично | Да |
| Яндекс 360 для бизнеса | SaaS | Да | Да | Нет | Да |
| МТТ / Viber for Business | SaaS | Уточнять | Ограничено | Нет | Нет |
| Microsoft Teams (GovCloud) | SaaS | Нет | Да | Нет | Нет |

## Симуляция фишинга: как провести правильно

### Правила эффективной симуляции

1. **Цель — обучение, не наказание.** Сотрудники, «попавшиеся», получают немедленный микро-курс (2–3 минуты), а не выговор.
2. **Реалистичность.** Используйте актуальные шаблоны: COVID, «обновление пароля», «посылка на почте», «важное письмо от HR».
3. **Разнообразие.** Ротируйте шаблоны раз в квартал — одни и те же письма быстро запоминаются.
4. **Метрики.** Отслеживайте: % открывших письмо, % перешедших по ссылке, % введших данные.
5. **Обратная связь.** После симуляции — общие результаты по организации (без персональных данных), разбор признаков фишинга.

### Инструменты

| Инструмент | Тип |
|---|---|
| GoPhish | Open source, self-hosted |
| KnowBe4 | SaaS |
| PT Security Awareness | SaaS, российский |
| Kaspersky Security Awareness | SaaS, российский |

### Пример метрик за год

```
Квартал 1: 45% открыли, 22% перешли по ссылке → провели тренинг
Квартал 2: 38% открыли, 15% перешли → улучшение
Квартал 3: 30% открыли, 9% перешли → продолжаем
Квартал 4: 25% открыли, 6% перешли → достигаем целевого уровня
```

Целевой показатель: не более 5% переходов по ссылке.

## Правила для сотрудников: памятка

Можно дать сотрудникам в виде карточки или включить в onboarding-материалы:

```
ПРОВЕРЯЙ ПЕРЕД ОТКРЫТИЕМ:
✓ Адрес отправителя — именно тот домен, что ожидаешь? (не support@company.ru.evil.com)
✓ Ссылка в письме — куда ведёт на самом деле? (наведи курсор, не кликай)
✓ Письмо просит срочно что-то сделать / требует пароль / обещает приз? → стоп.

НЕ ОТПРАВЛЯЙ ПО КОРПОРАТИВНОЙ ПОЧТЕ:
✗ Пароли и ключи доступа
✗ ПДн клиентов и сотрудников на личные ящики
✗ Договоры и финансовые документы в незашифрованном виде — сторонним сервисам

ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК:
→ Не закрывай окно, не перезагружай компьютер
→ Позвони / напиши в ИБ: [контакт {{ОТВЕТСТВЕННЫЙ_ЗА_ИБ}}]
→ Не стесняйся — сообщить о подозрительном письме лучше, чем промолчать
```
