# POL-SEC-001 — Политика реагирования на инциденты ИБ

Определяет принципы, роли и порядок реагирования на инциденты информационной безопасности: от обнаружения до постинцидентного анализа.

## Кому нужна

**Каждой организации**, у которой есть IT-инфраструктура. Инциденты происходят у всех — вопрос в том, управляемо ли реагирование или хаотично. Это одна из первых политик, внедряемых после зонтичной Политики ИБ (этап 1 по ROADMAP.md).

## Что покрывает

- Классификацию инцидентов по уровням критичности P1–P4 с временными нормативами реагирования
- Шестифазный процесс: Подготовка → Обнаружение → Сдерживание → Расследование → Восстановление → Постинцидентный анализ
- Роли: руководитель реагирования, команда IRT, владелец Политики
- Обязательные уведомления регуляторов (РКН, НКЦКИ) с таблицей сроков
- Правила внутренних и внешних коммуникаций при инциденте
- Требования к документированию и метрики (MTTD, MTTR)

**Не покрывает:**
- Технические процедуры форензики (см. POL-FOR-001 — отдельная политика)
- Непрерывность бизнеса и восстановление после катастроф (см. POL-BCP-001)
- Конкретные процедурные сценарии (playbooks) — это операционный уровень, ниже политики

## Контекст применения в РФ

**ФЗ-152 (персональные данные):** операторы обязаны уведомлять Роскомнадзор об инцидентах, приведших к неправомерной передаче ПДн, в течение **72 часов** с момента обнаружения (ст. 21 ч. 3.1). Задержка с уведомлением — самостоятельное нарушение.

**187-ФЗ (КИИ):** субъекты критической информационной инфраструктуры обязаны уведомлять НКЦКИ об инцидентах. Срок — 3 часа для значимых объектов первой категории. Применимо только организациям, прошедшим категорирование.

**ФСТЭК Приказ 17/21/239:** требования ОБЖ.1–ОБЖ.5 прямо предписывают наличие процессов обнаружения и реагирования на инциденты. Эта политика закрывает данные требования.

## Что нужно подготовить заранее

1. **Канал сообщения об инцидентах** — конкретный адрес/номер, доступный 24/7 для P1
2. **Контактный список IRT** — ФИО, роли, телефоны, включая резервные на нерабочее время
3. **Система учёта инцидентов** — ITSM-система, SIEM или минимум защищённая таблица
4. **Наличие резервных копий** — восстановление без них невозможно (POL-DAT-002)
5. **Понимание, являетесь ли вы субъектом КИИ** — влияет на п. 7.3 TEMPLATE.md
