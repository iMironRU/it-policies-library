# История изменений — POL-SVC-001 Политика управления IT-услугами

## [1.0.1] — 2026-10-03

### Исправления (по результатам кросс-политического ревью)
- §5.5: добавлено правило приоритета при квалификации ИБ-инцидентов — если инцидент классифицирован службой ИБ согласно POL-SEC-001, его приоритет определяется по критериям POL-SEC-001, а не по матрице §5.2; утечка ПДн / компрометация учётных данных → автоматически P1; устраняет потенциальный конфликт в эскалационной цепочке

## [1.0.0] — 2026-10-03

### Added
- Первоначальная версия шаблона
- Каталог IT-услуг: 7 категорий (рабочее место, управление доступом, коммуникации, инфраструктура, бизнес-приложения, разработка, ИБ); процесс ввода/вывода услуг с 30-дневным уведомлением
- Управление инцидентами: классификация P1–P4 по матрице воздействие × срочность; таблица SLA по всем приоритетам; 7-шаговая процедура обработки; PIR для P1 и повторяющихся P2 (срок — 5 рабочих дней)
- Разграничение IT-инцидентов и инцидентов ИБ: параллельная передача в службу ИБ при признаках угрозы
- Управление запросами: стандартные (из каталога, без дополнительного согласования) и нестандартные; запросы на доступ требуют согласования владельца ресурса
- Управление проблемами: RCA, известные ошибки, база знаний; привязка к {{ПОРТАЛ_САМООБСЛУЖИВАНИЯ}}
- Управление уровнями сервиса: целевые показатели ≥95% для P1/P2, ≥90% для P3/P4; ежемесячная отчётность (5 разделов); SLA с внешними подрядчиками
- Управление конфигурациями: CMDB со структурой (аппарат, ПО, виртуальные/облачные активы, взаимосвязи); ежегодный аудит
- Непрерывность IT-услуг: привязка к политике BCP; участие в тестировании RTO/RPO
- Раздел ответственности: 5 ролей (IT-директор, руководитель СП, специалисты, Service Owner, пользователи)
- Раздел контроля: 4 горизонта (реальное время, еженедельно, ежемесячно, ежегодно)
- GUIDE.md: ориентиры SLA по размеру команды, пошаговое руководство по внедрению, частые ошибки, адаптация для малого бизнеса и аутсорсинговой модели, связь с ISO/IEC 20000-1 и ITIL 4

### Исправления (по результатам AI-ревью)
- §5.2: добавлена матрица приоритизации воздействие × срочность → P1–P4 (вместо только текстового описания критериев); добавлена пометка о праве пользователя оспорить приоритет
- §6: добавлен подраздел §6.2 «Сроки выполнения запросов» с таблицей SLA по типам service requests и соответствующими плейсхолдерами (доступ, ПО, оборудование, консультация)
- §8: добавлен подраздел §8.2 «OLA между подразделениями IT» — термин OLA, определённый в §3, теперь используется в тексте политики
