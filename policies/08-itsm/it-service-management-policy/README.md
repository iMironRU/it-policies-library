# POL-SVC-001 — Политика управления IT-услугами

**Идентификатор:** POL-SVC-001  
**Статус:** draft  
**Зрелость:** ◆ Standard  
**Владелец:** CIO / IT-директор

---

## Зачем эта политика

IT-служба в большинстве организаций работает в режиме «очереди к специалисту»: кто добрался лично — получил помощь, кто не знает как попросить — ждёт. Нет метрик, нет обязательств, нет понимания что и за сколько делается.

Эта политика решает три связанных проблемы:

1. **Непредсказуемость.** Пользователи не знают, когда будет решена их задача. Тот, кто кричит громче, получает помощь быстрее — вне зависимости от реальной бизнес-критичности.
2. **Невидимость.** Руководство не видит, чем занята IT-служба, сколько заявок обрабатывается, где узкие места.
3. **Отсутствие улучшений.** Без данных нет оснований ни для ресурсных решений, ни для совершенствования сервиса.

Политика вводит: единую точку контакта, измеримые SLA по приоритетам, обязательную регистрацию всех обращений, процесс управления проблемами (не только симптомами), ежемесячную отчётность.

---

## Что покрывает шаблон

- **Каталог IT-услуг** — 7 категорий (рабочее место, доступ, коммуникации, инфраструктура, бизнес-приложения, разработка, ИБ); процесс ввода/вывода услуг
- **Управление инцидентами** — приоритизация P1–P4 по матрице воздействие × срочность; SLA по приоритетам; 7-шаговая процедура; PIR для критических инцидентов
- **Запросы на обслуживание** — стандартные (из каталога) и нестандартные
- **Управление проблемами** — RCA, известные ошибки, база знаний
- **Управление уровнями сервиса** — ежемесячная отчётность, целевые показатели (≥95% для P1/P2, ≥90% для P3/P4), SLA с внешними подрядчиками
- **Управление конфигурациями** — CMDB, ежегодный аудит
- **Непрерывность IT-услуг** — привязка к политике BCP, RTO/RPO для критичных услуг

## Контекст применения

**Кому нужна эта политика:**

- Компаниям от ~50 сотрудников, где IT-служба отдельна от бизнеса
- Организациям, внедряющим или обновляющим ITSM-систему (Jira SM, ServiceNow, 1С:ITIL и др.)
- Организациям, получившим претензии на непрозрачность IT-обслуживания
- Организациям, планирующим аутсорсинг IT или работу с несколькими IT-подрядчиками

**Минимальный набор для запуска:**

Политика опирается на `{{СИСТЕМА_УЧЁТА_ЗАЯВОК}}` — без инструмента регистрации заявок она становится декларативной. Перед внедрением нужно выбрать систему.

## Нормативная база

Шаблон ориентирован на лучшие практики, а не на обязательные требования конкретного регулятора. Основные источники:

- **ISO/IEC 20000-1:2018** — системные требования к управлению IT-услугами
- **ITIL 4** — практики управления IT-сервисами (в части концепций, а не как дословный перевод)
- **ISO/IEC 27001:2022 A.5.35** — независимая проверка информационной безопасности

Если организация проходит сертификацию по ISO/IEC 20000-1 — эта политика служит верхнеуровневым документом; конкретные процедуры (SOP по управлению инцидентами, изменениями и т.д.) выносятся в отдельные регламенты.
