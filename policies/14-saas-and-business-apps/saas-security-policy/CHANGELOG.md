# История изменений — POL-SAA-001 Политика безопасности SaaS и бизнес-приложений

## [1.0.0] — 2026-10-02

### Added
- Первоначальная версия шаблона
- Четырёхуровневая классификация приложений по уровню риска (Критический / Высокий / Средний / Низкий) на основе типов обрабатываемых данных
- Реестр приложений: обязательные атрибуты (вендор, уровень риска, владелец, типы данных, ПДн, страна хранения, DPA, SSO, SCIM, дата оценки)
- Ревизия реестра с периодичностью {{СРОК_РЕВИЗИИ_ПРИЛОЖЕНИЙ}}
- Процесс согласования новых приложений: заявка → оценка безопасности за {{СРОК_ОЦЕНКИ_БЕЗОПАСНОСТИ}} → юридическое согласование для критичных → онбординг в IdP
- Матрица оценки безопасности вендора: DPA, страна хранения, шифрование, сертификаты (ISO 27001, SOC 2 Type II), SSO/SCIM, экспорт/удаление данных
- Требования к аутентификации: SSO обязателен для Критических и Высоких (и при ≥ {{ПОРОГ_ПОЛЬЗОВАТЕЛЕЙ_SSO}} пользователях); MFA обязательна; SCIM рекомендуется
- Управление жизненным циклом доступа: провизия через IdP/SCIM, деактивация при увольнении за {{СРОК_ДЕАКТИВАЦИИ_УВОЛЕННОГО}}, ревизия прав {{СРОК_РЕВИЗИИ_ДОСТУПОВ}}
- Матрица допустимого размещения данных по классификации × уровню приложения
- Требования ФЗ-152 для ИСПДн в облаке: локализация (ч. 5 ст. 18), договор поручения обработки (ст. 6)
- Требования к экспорту данных и подтверждению удаления при расторжении контракта
- Требования к безопасности API-интеграций: хранение ключей в менеджере секретов, минимальные права, ротация; контроль low-code автоматизаций (Zapier/Make/n8n) и плагинов
- Процедура вывода приложения из эксплуатации: 7 шагов (экспорт → деактивация пользователей → отзыв интеграций → подтверждение удаления → расторжение)
- Меры по выявлению теневых IT: DNS/прокси-мониторинг, анализ SSO-логов, опросы, финансовый мониторинг
- Матрица ответственности: ИБ / Бизнес-владелец / IT / Сотрудники / Юристы / Руководство
- Руководство по применению (GUIDE.md): трёхэтапная дорожная карта, типичные ловушки (Shadow IT, DPA, локализация), чеклист оценки безопасности вендора, автоматизация offboarding через SCIM (Azure AD / Okta), минимальная структура реестра, рекомендуемые значения плейсхолдеров
