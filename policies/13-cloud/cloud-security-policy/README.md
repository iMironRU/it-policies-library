# POL-CLD-001 — Политика облачной безопасности

**Идентификатор:** POL-CLD-001  
**Статус:** draft  
**Зрелость:** ◆ Standard  
**Владелец:** CISO  

---

## Зачем нужна эта политика

Облачные сервисы стали стандартной инфраструктурой, но приносят новые риски: неверно сконфигурированные ресурсы, избыточные права, открытые хранилища данных и вопросы о месте хранения — всё это реальные угрозы, ежедневно приводящие к утечкам данных.

Эта политика устанавливает единые требования безопасности для работы с любыми облачными сервисами — от IaaS (виртуальные серверы) до SaaS (корпоративные приложения). Она отвечает на вопросы: как оценить провайдера, какие данные можно размещать в облаке, как управлять доступом, что обязательно журналировать и как соблюдать ФЗ-152 при облачной обработке ПДн.

## Как использовать этот шаблон

1. Заполните плейсхолдеры — особое внимание на `{{ПОРОГ_КРИТИЧНОСТИ_ДАННЫХ}}` и `{{РЕЕСТР_ОБЛАЧНЫХ_СЕРВИСОВ}}`.
2. Пройдитесь по таблице разделённой ответственности в §4 и отметьте, что реально делается, а что нет.
3. Проведите инвентаризацию текущих облачных сервисов и создайте реестр.
4. Проверьте каждый действующий CSP по критериям §5.2.
5. Особо разберитесь с §10 (локализация ПДн) — это частая зона нарушений.
6. Подробные советы — в `GUIDE.md`.

## Ограничения шаблона

- Шаблон покрывает общие требования для всех CSP. Для конкретного провайдера (Яндекс Облако, AWS, Azure) потребуются дополнительные технические стандарты с конкретными настройками.
- Шаблон не описывает Container Security, Kubernetes Security и Serverless Security — это темы для отдельных стандартов.
- Для финансовых организаций применяются дополнительные требования ГОСТ Р 57580 и ЦБ РФ.
