# GUIDE — POL-CMP-001 Политика управления соответствием требованиям

Руководство по внедрению: как построить реестр требований, провести gap-анализ и подготовиться к проверке регулятора.

---

## Шаг 1. Определить применимые требования

### Четыре вопроса для скоупинга

Перед тем как заполнять реестр, ответьте на четыре вопроса о вашей организации:

| Вопрос | Если «да» — применимо |
|---|---|
| Обрабатываете ПДн физических лиц? | ФЗ-152, РКН |
| Эксплуатируете ГИС или ИС органов власти? | Приказ ФСТЭК №17 |
| Относитесь к субъектам КИИ (12 отраслей)? | ФЗ-187, Приказ ФСТЭК №239 |
| Вы банк или небанковская финансовая организация? | ГОСТ Р 57580, требования ЦБ РФ |

12 отраслей — субъекты КИИ (ФЗ-187 ст. 2): здравоохранение, наука, транспорт, связь, энергетика, банки и финансы, ТЭК, атомная энергетика, оборонная промышленность, ракетно-космическая, горнодобывающая, металлургическая и химическая промышленность. Если ваша деятельность попадает в эту сферу — обязательна консультация с юристом о статусе субъекта КИИ.

## Шаг 2. Построить реестр требований

### Минимальная структура реестра

```
Источник | Норма | Обязательность | Применимо к | Контроль | Статус | Дата проверки | Ответственный
```

Пример строки:

```
ФЗ-152 | Ст. 21 — уведомление РКН при утечке | Обязательное | Все ИС с ПДн | POL-SEC-001 §7 + процедура уведомления | Частично соответствует | 2026-09-15 | CISO
```

### Инструменты для реестра

| Уровень | Инструмент |
|---|---|
| Базовый | Excel / Google Sheets — быстро, понятно, достаточно для старта |
| Средний | Confluence + шаблон таблицы — удобно для команды |
| Зрелый | GRC-система: R-Vision, 1С:ГРЦ, СёрчИнформ, ПТ, OpenGRC |

Начните с Excel — лучше работающий Excel, чем незаполненная дорогая GRC.

## Шаг 3. Провести gap-анализ

### Алгоритм

1. Для каждого требования в реестре определите: какие конкретно технические и организационные меры закрывают это требование.
2. Проверьте наличие каждой меры: политика существует и актуальна? Техническая мера настроена и работает? Есть доказательства (лог, скриншот, протокол)?
3. Присвойте статус: Соответствует / Частично / Не соответствует / Не применимо.
4. Для «Частично» и «Не соответствует» — зафиксируйте, чего конкретно не хватает.

### Типичные несоответствия в российских организациях

| Требование | Частое несоответствие |
|---|---|
| ФЗ-152 — политика обработки ПДн | Не опубликована или устарела |
| ФЗ-152 — согласие на обработку ПДн | Нет или не охватывает все цели обработки |
| ФЗ-152 ст. 21 — уведомление РКН | Нет процедуры; сроки (24ч/72ч) не соблюдаются |
| ФСТЭК Приказ №21 — модель угроз | Не разработана или не актуализирована |
| Приказ №239 — категорирование КИИ | Не проведено или результаты не поданы в ФСТЭК |
| Любой стандарт — обучение сотрудников | Нет документации о прохождении |
| Любой стандарт — процедура управления инцидентами | Есть политика, нет отработанной процедуры |

## Шаг 4. Подготовиться к проверке регулятора

### Что проверяет РКН (ФЗ-152)

1. Уведомление об обработке ПДн (реестр операторов ПДн — наличие записи).
2. Политика обработки ПДн — опубликована, актуальна, содержит обязательные сведения (ст. 18.1).
3. Согласия субъектов ПДн — есть, охватывают цели обработки.
4. Договоры с операторами/обработчиками — есть, содержат требования по безопасности.
5. Технические меры защиты — описаны, реализованы, соответствуют УЗ.
6. Порядок реагирования на обращения субъектов ПДн — есть, соблюдается.
7. Локализация: ПДн граждан РФ первично записываются в российские ИС.

### Что проверяет ФСТЭК (Приказ №17, №21, №239)

1. Наличие модели угроз и нарушителя.
2. Документация системы защиты (технический проект, ТЗ на СЗИ).
3. Наличие сертифицированных СЗИ.
4. Журналы событий ИБ и аудита.
5. Для КИИ — результаты категорирования, поданные в ФСТЭК.
6. Организационные меры: назначен ответственный, есть инструкции, сотрудники обучены.

### Документы, которые должны быть наготове

```
□ Реестр требований с актуальными статусами
□ Политика обработки ПДн (публичная страница)
□ Приказ о назначении ответственного за ПДн / ИБ
□ Модель угроз
□ Перечень ИС с обоснованием требований к защите
□ Договоры с обработчиками ПДн (со всеми требованиями)
□ Журналы обучения сотрудников (подписи или электронные записи)
□ Планы устранения несоответствий (для открытых несоответствий)
□ Протокол последней оценки соответствия
```

## Уведомление РКН при инциденте с ПДн

С 2023 года ФЗ-152 обязывает операторов уведомлять РКН об инцидентах с ПДн в жёсткие сроки.

### Сроки

- **24 часа** — первичное уведомление (факт инцидента, предварительная оценка, предпринятые меры).
- **72 часа** — детальное уведомление (причины, перечень затронутых субъектов, принятые и планируемые меры).

### Как уведомить

Уведомление подаётся через **Портал персональных данных** (pd.rkn.gov.ru) в личном кабинете оператора. При отсутствии ЭЦП — по официальным каналам РКН.

Важно: если инцидент связан со значимым объектом КИИ — параллельно уведомляется НКЦКИ (3 часа по Приказу №239).

## GRC-системы для российского рынка

| Решение | Тип | Особенности |
|---|---|---|
| R-Vision Risk Manager | On-premise / SaaS | Реестр рисков, управление несоответствиями, шаблоны для ФСТЭК/РКН |
| СёрчИнформ SIEM + ГРЦ | On-premise | Интеграция с SIEM; шаблоны российских стандартов |
| 1С:ГРЦ | On-premise | Привычная среда для российских компаний, интеграция с 1С |
| ПТ Compliance Manager | On-premise | Автоматическая оценка технических контролей через интеграцию с PT |
| OpenGRC (open source) | Self-hosted | Бесплатно, гибко, требует настройки под российские стандарты |

## Признаки зрелой программы комплаенс

```
Уровень 1 (Начальный):
  ✓ Есть реестр требований (хотя бы в Excel)
  ✓ Проведена хотя бы одна оценка соответствия
  ✓ Назначен ответственный за комплаенс

Уровень 2 (Повторяемый):
  ✓ Оценки проводятся по расписанию
  ✓ Несоответствия документируются и отслеживаются
  ✓ Руководство получает регулярные отчёты

Уровень 3 (Управляемый):
  ✓ Маппинг контролей на все применимые требования
  ✓ Доказательства соответствия собираются системно
  ✓ Программа обучения охватывает 100% сотрудников

Уровень 4 (Оптимизированный):
  ✓ GRC-система автоматизирует сбор доказательств
  ✓ Комплаенс встроен в цикл разработки и изменений
  ✓ Внешний аудит подтвердил соответствие
```
