# История изменений — POL-ARC-001 Политика управления IT-архитектурой

## [1.0.0] — 2026-10-03

### Added
- Первоначальная версия шаблона
- 6 архитектурных принципов: бизнес-согласованность, повторное использование, открытые стандарты и интероперабельность, Security by Design, масштабируемость и сопровождаемость, управление данными
- Реестр технологий: 4 категории (одобрено/условно/оценивается/запрещено); процесс обновления; срок миграции устаревших технологий через `{{СРОК_ВЫВОДА_УСТАРЕВШИХ}}`
- Архитектурный процесс: критерии обязательного ревью (стоимость, пользователи, ПДн, внешние интеграции); упрощённое ревью; 5-шаговая процедура АРБ; последствия запуска в обход ревью
- ADR (Architecture Decision Records): требования к содержанию (контекст, варианты, решение, последствия, статус); хранение в git `docs/adr/`; процедура пересмотра
- Управление технологическим долгом: реестр долга, ежегодная приоритизация с бюджетированием, правила документирования нового долга
- Стандарты интеграции: API-first, OpenAPI/Swagger, запрет прямого доступа к СУБД, интеграционная платформа
- Матрица ответственности: 6 ролей (IT-директор, главный архитектор, АРБ, руководители проектов, IT-специалисты, бизнес)
- GUIDE.md: адаптация по размеру организации, практики управления долгом, антипаттерны (АРБ как тормоз, формальные ADR, реестр без EOL-мониторинга)

### Исправления (по результатам AI-ревью)
- §4.3: удалён список конкретных протоколов (REST, OAuth 2.0, SQL, LDAP/SCIM) — он устаревает быстрее документа; заменён ссылкой на {{РЕЕСТР_ТЕХНОЛОГИЙ}}
- §5.1: разделены категории «Запрещено / Устаревшее» → два отдельных статуса с разными режимами управления (EOL: плановая миграция 24 мес.; Запрещено: немедленная изоляция)
- §7.1: добавлена обязательная структура ADR (Nygard: Заголовок, Статус, Контекст, Варианты, Принятое решение, Последствия); правило immutability — изменения только через новый ADR `Supersedes: ADR-NNN`
