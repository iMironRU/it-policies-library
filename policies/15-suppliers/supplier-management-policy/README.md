# POL-SUP-001 — Политика управления подрядчиками

**Статус:** draft · **Зрелость:** ◆ Standard · **Владелец:** CISO

## Зачем нужен этот шаблон

Подрядчики — один из наиболее распространённых векторов утечки данных и компрометации инфраструктуры. Взломы через стороннего IT-поставщика, утечки через облачный сервис, несвоевременно заблокированные учётные записи уволенных подрядчиков — классические сценарии, которые решаются формализованными требованиями к цепочке поставок.

Этот шаблон охватывает полный жизненный цикл отношений с подрядчиком:

1. **Отбор** — оценка безопасности до заключения договора
2. **Договор** — обязательные и дополнительные требования ИБ в тексте договора
3. **Доступ** — именные учётные записи, минимальные привилегии, куратор
4. **Контроль** — мониторинг активности, плановые проверки критичных подрядчиков
5. **Завершение** — отзыв доступа в установленный срок, уничтожение данных

## Когда применять

Шаблон применим для любой организации, привлекающей внешних исполнителей с доступом к корпоративным системам или данным: IT-аутсорсинг, бухгалтерия на аутсорсе, облачные провайдеры, консультанты, разработчики.

Для организаций с небольшим числом подрядчиков (до 5–10 активных) некоторые процедуры можно упростить — см. GUIDE.md.

## Ключевые решения при адаптации

- **Что считать критичным подрядчиком** — зависит от того, к каким данным и системам он имеет доступ. Заполните `{{ПОРОГ_КРИТИЧНОСТИ}}`.
- **Нужно ли DPA** — если подрядчик обрабатывает ПДн, DPA обязателен по ФЗ-152 ст. 6 ч. 3.
- **Срок отзыва доступа** — рекомендуется не более 1 рабочего дня; для систем с ПДн — немедленно.
