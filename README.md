# Библиотека IT-политик для организаций

[![License: CC BY-SA 4.0](https://img.shields.io/badge/License-CC%20BY--SA%204.0-lightgrey.svg)](https://creativecommons.org/licenses/by-sa/4.0/)
![Статус: в разработке](https://img.shields.io/badge/Статус-в%20разработке-yellow)
![Язык: русский](https://img.shields.io/badge/Язык-русский-blue)

Открытая библиотека шаблонов IT-политик, регламентов и стандартов для русскоязычных организаций. Все шаблоны проработаны с учётом ISO/IEC 27001:2022, NIST CSF 2.0, CIS Controls v8, ITIL 4 и российской регуляторной базы (ФСТЭК, ФСБ, РКН).

> **Статус.** В активной разработке. Каркас и эталонные шаблоны готовы — остальное наполняется. **PR-ы приветствуются** — см. [CONTRIBUTING.md](./CONTRIBUTING.md).

---

## Зачем эта библиотека

В большинстве русскоязычных организаций IT-документация либо отсутствует, либо состоит из переписанных под копирку шаблонов из интернета без учёта связности, зрелости и реальной применимости. Эта библиотека решает три проблемы:

1. **Полнота** — каталог из 24 доменов покрывает ISO 27001, NIST CSF, ITIL 4 и российскую регуляторику в одном месте.
2. **Связность** — каждая политика имеет машиночитаемые метаданные о зависимостях. Видно, что нужно внедрить раньше, что — позже.
3. **Применимость** — маркеры зрелости (★ ◆ ▲) и условности (ⓘ) помогают понять, что нужно вам, а что — нет.

## Как пользоваться — три двери

### 🚀 Я только начинаю
Возьмите [минимальный стартовый пакет](./packs/minimum-starter/). Это 13–14 базовых политик, которые покрывают 80% типовых рисков для средней организации.

### 🎯 У меня есть конкретная цель
Выберите готовый набор под вашу задачу:

| Пакет | Для кого |
|---|---|
| [`minimum-starter`](./packs/minimum-starter/) | Маленькая компания, базовый минимум |
| `iso-27001-aligned` | Готовитесь к сертификации ISO 27001 *(в работе)* |
| `152-fz-aligned` | Работаете с ПДн граждан РФ *(в работе)* |
| `kii-subject` | Субъект критической инфраструктуры *(в работе)* |
| `software-development` | IT-компания, разрабатываете ПО *(в работе)* |
| `cloud-first` | Работаете преимущественно в облаке *(в работе)* |

### 🔍 Я знаю, что мне нужно
- [Индекс по доменам](./docs/BY-DOMAIN.md) — 24 области IT
- [Индекс по сценариям](./docs/BY-USE-CASE.md) — «у меня случилось X»
- [Индекс по регуляторам](./docs/BY-REGULATOR.md) — ФСТЭК, ISO, NIST, и т.д.

### 🗺️ Хочу видеть всю карту целиком
- [Полный каталог из 24 доменов](./docs/CATALOG.md) — ~250 пунктов того, что вообще может существовать в IT-документации. Карта местности для понимания, что уже есть и куда расти.

## Структура репозитория

```
it-policies-library/
├── README.md                 ← вы здесь
├── CLAUDE.md                 рабочие соглашения для людей и AI
├── CONTRIBUTING.md           как контрибьютить
├── LICENSE                   CC-BY-SA 4.0
├── CHANGELOG.md              история изменений библиотеки
│
├── docs/                     справочные документы
│   ├── ROADMAP.md            с чего начать → куда дальше
│   ├── MATURITY-LAYERS.md    объяснение ★ ◆ ▲
│   ├── DEPENDENCIES.md       граф связей (Mermaid)
│   ├── GLOSSARY.md           термины
│   ├── BY-DOMAIN.md          индекс по доменам
│   ├── BY-USE-CASE.md        индекс по сценариям
│   └── BY-REGULATOR.md       индекс по регуляторам
│
├── policies/                 сами шаблоны политик (по 24 доменам)
│   ├── _TEMPLATE/            эталонная структура шаблона
│   ├── 01-strategic/
│   ├── 02-access-control/
│   ├── 03-data-governance/
│   ├── ... (всего 24 домена)
│   └── 24-meta-policies/
│
├── packs/                    готовые наборы политик
│   └── minimum-starter/
│
├── tools/                    автоматизация
│   ├── validate-metadata.py
│   └── generate-dependency-graph.py
│
└── .github/                  GitHub-конфигурация
    ├── ISSUE_TEMPLATE/
    ├── PULL_REQUEST_TEMPLATE.md
    └── workflows/
```

Каждая папка политики содержит:
- `README.md` — описание и контекст
- `TEMPLATE.md` — сам шаблон с плейсхолдерами
- `GUIDE.md` — как применять
- `metadata.yml` — машиночитаемые метаданные
- `CHANGELOG.md` — история этого шаблона
- `EXAMPLES/` — опционально, анонимизированные примеры
